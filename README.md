# CAP Education — бот выдачи сертификатов

Телеграм-бот ([@SertCapEDUbot](https://t.me/SertCapEDUbot)), который заменяет ручную работу
при выпуске ученика: рисует сертификат по шаблону, ведёт учёт кодов в Google-таблице
и отправляет пакет документов родителю на почту.

Ментор присылает ФИО ученика — бот делает остальное:

1. находит ученика в **Альфа-CRM** и берёт ФИО родителя и его email;
2. занимает первый свободный код `CAP-XXXXXX` в таблице «Оффбординг» и заполняет строку
   (ФИО, ментор, ✓ Сертификат, курс, дата, «Действителен», ✓ Благодарственное письмо);
3. рисует сертификат: ФИО, номер, дата, QR со ссылкой на `capedu.kz/verify.html?id=<код>`;
4. добавляет благодарственное письмо родителю (для казахских шаблонов — «Алғыс хат»)
   и бонусные сертификаты;
5. отправляет пакет в Telegram и, по подтверждению, письмо родителю с вложениями.

## Возможности

| Возможность | Описание |
|---|---|
| Пакетная выдача | Несколько учеников одним сообщением, каждый с новой строки |
| Подстановка из CRM | Родитель и почта берутся из карточки, включая архивные (выпускники) |
| Учёт кодов | Один ученик — один код; строка в таблице заполняется автоматически |
| Бонусные сертификаты | ИИ, Компьютерная грамотность, Мобилография — под кодом основного курса, без QR и без строки в таблице |
| Письмо родителю | Шаблон на русском, казахском или английском, вложения, скидка 30% на следующий курс |
| Подтверждение отправки | Письмо уходит только после нажатия кнопки — защита от опечатки в адресе |
| Устойчивость к сети | Повторы отправки, команда `/resend` вместо повторной выдачи кода |
| Работа без таблицы | Если Google-доступ не настроен, код указывается вручную: `CAP-XXXXXX Ученик / Родитель` |

## Структура проекта

```
cert_bot.py           точка входа: команды, кнопки, сценарий выдачи
render.py             наложение ФИО, номера, даты и QR на шаблон (Pillow)
qr.py                 генерация QR со ссылкой проверки
sheets.py             Google Sheets API (OAuth) + запасной путь через Apps Script
crm.py                Альфа-CRM: поиск ученика, ФИО родителя, почта, телефон
mailer.py             сборка и отправка письма через Gmail API
google_login.py       одноразовый вход в Google, создаёт token.json
check.py              самопроверка настроек перед запуском
config.json           шаблоны, курсы, координаты полей, скрытые менторы
requirements.txt      зависимости
.env.example          образец настроек
email_templates.json  тексты писем (ru/kz/en) и списки курсов для скидки
apps_script.gs        запасной бэкенд для таблицы, если OAuth недоступен
                      (перед установкой подставить секрет из APPS_SCRIPT_SECRET)
templates/            чистые PNG-шаблоны 2000×1425 (казахская благодарность 2000×1414)
out/                  готовые файлы и QR (создаётся автоматически)
issued.csv            журнал выдач: код, ФИО, курс, дата
emails.csv            журнал отправленных писем
```

Секреты (`.env`, `credentials.json`, `token.json`) и журналы в git не попадают — см. `.gitignore`.

## Требования

- Python 3.12, виртуальное окружение `.venv`
- Библиотеки: `pytelegrambotapi`, `pillow`, `qrcode`, `requests`, `gspread`,
  `google-auth`, `google-auth-oauthlib`, `google-api-python-client`
- Google-аккаунт с правами редактора на таблицу «KPI Куратор 2026» (лист «Оффбординг»)
- Проект Google Cloud с включёнными **Google Sheets API** и **Gmail API**
- Доступ к API Альфа-CRM (email + ключ `v2api`)

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

## Настройка

### 1. Файл `.env`

За основу взять `.env.example`:

```bash
cp .env.example .env
```

```ini
CERT_BOT_TOKEN=<токен от @BotFather>
CERT_VERIFY_URL=https://capedu.kz/verify.html?id={code}
CERT_SHEET_ID=<id Google-таблицы из адресной строки>
CERT_ADMINS=                      # пусто — доступ у всех; иначе список chat_id через запятую

ALFA_HOST=<поддомен>.s20.online
ALFA_EMAIL=<email в Альфа-CRM>
ALFA_API_KEY=<ключ API v2api>
ALFA_BRANCH=3                     # id филиала (виден в адресе: /company/3/)
```

### 2. Доступ к Google

1. В Google Cloud создать проект, включить **Google Sheets API** и **Gmail API**.
2. **Google Auth Platform → Audience**: тип **Internal** (для домена организации).
3. **Clients → Create client → Desktop** — скачать JSON, сохранить как `credentials.json`.
4. Выполнить одноразовый вход:

```bash
.venv/bin/python google_login.py
```

Откроется браузер; войти аккаунтом с доступом к таблице и разрешить два доступа:
таблицы и отправку писем. Появится `token.json`, он обновляется сам.

### 3. Шаблоны

PNG из Canva без ФИО, номера, даты и заглушки под QR. Координаты полей — в `config.json`
в долях от размера картинки, поэтому не зависят от разрешения экспорта:

```json
"python": {
  "title": "🐍 Python", "file": "templates/sert_python.png", "kind": "sert",
  "course": "Python", "lang": "ru", "letter": "blago",
  "fields": {
    "name":   {"font": "name", "x": 0.4995, "y": 0.5305, "size": 0.0702, "color": "#FCF98D"},
    "qr":     {"type": "image", "box": [0.609, 0.8175, 0.6865, 0.9256]},
    "number": {"font": "small", "x": 0.706, "y": 0.8786, "size": 0.0217, "prefix": "№ "},
    "date":   {"font": "small", "x": 0.849, "y": 0.8786, "size": 0.0217}
  }
}
```

Ключевые поля шаблона: `kind` (`sert` или `blago`), `course` (значение для колонки «Курс»),
`lang` (язык письма), `letter` (какую благодарность прикладывать), `bonus` (доступен как бонусный).

### 4. Самопроверка

```bash
.venv/bin/python check.py
```

Скрипт ничего не меняет и не отправляет: проверяет токен, шаблоны и шрифты, доступ
к таблице, список менторов, связь с CRM, разрешение на отправку писем и тексты писем.

### 5. Запуск

```bash
.venv/bin/python cert_bot.py
```

Чтобы Mac не засыпал, пока бот работает:

```bash
caffeinate -i .venv/bin/python cert_bot.py
```

Остановка: `Ctrl+C` или `pkill -f cert_bot.py`.

## Использование

Сценарий: **курс → ментор → бонусы → список ФИО → подтверждение письма**.

```
Асылхан Адемай
Бахытұлы Исмаил
```

Если ученика нет в CRM или есть однофамильцы, данные указываются вручную:

```
Иванов Иван / Иванова Мария / mama@gmail.com
```

Разделителем может быть `/`, `;` или ` - `.

### Команды

| Команда | Действие |
|---|---|
| `/start` | Меню курсов и благодарностей |
| `/crm Фамилия Имя` | Что есть в CRM: родитель, почта, телефон |
| `/stats` | Сколько кодов свободно и выдано |
| `/resend CAP-XXXXXX` | Прислать готовый пакет ещё раз, без нового кода |
| `/revoke CAP-XXXXXX` | Поставить статус «Отозван» |
| `/log` | Последние 20 выдач |

## Как устроена таблица

Лист «Оффбординг» (`gid=678851710`):

| Колонка | Назначение |
|---|---|
| A | `ID (код)` — заранее сгенерированные `CAP-XXXXXX` |
| B | ФИО ученика |
| C | Ментор — строгий выпадающий список |
| D | Комментарий ментора |
| E | ✓ Сертификат |
| F | ✓ Выпускной |
| G | Курс |
| H | Дата получения |
| I | Статус: «Свободен» / «Действителен» / «Отозван» |
| J, K | Формулы: ссылки на QR и страницу проверки |
| L | ✓ Благодарственное письмо |

Свободной считается строка, где есть код, пустое ФИО и статус «Свободен».
Строки с заполненным ФИО бот не трогает, даже если статус остался «Свободен».

Список менторов хранится в проверке данных колонки C. Чтобы добавить ментора, внесите его
в этот список в таблице — бот подхватит изменение сам. Неактуальные имена можно скрыть
из кнопок бота через `mentors_hidden` в `config.json`, оставив их валидными в таблице.

## Письма

Тексты и списки курсов для скидки — в `email_templates.json`:

```json
"next_courses": ["Frontend", "Backend", "CS50", "Mobile", "Web"],
"next_courses_by_course": {
  "web":    ["Backend", "CS50", "Mobile"],
  "python": ["Frontend", "Backend", "CS50", "Mobile"]
}
```

Пройденный курс из списка убирается автоматически. Язык письма определяется полем `lang`
шаблона. После правки файла бота нужно перезапустить.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `The caller does not have permission` | У вошедшего аккаунта нет доступа к таблице — выдать права редактора |
| `Insufficient authentication scopes` | Нет разрешения Gmail — повторить `google_login.py` |
| `Gmail API has not been used in project` | Включить Gmail API в том же проекте Google Cloud |
| Ученик не найден в CRM | Карточка в архиве — бот ищет и там; проверьте написание через `/crm` |
| Файл не отправился в Telegram | Слабая сеть. Код уже занят — использовать `/resend`, не выдавать заново |
| Имя ментора не принимается | Значения вне списка колонки C Google отклоняет — добавьте ментора в список |

## Безопасность

- Токены и ключи хранятся только в `.env`, `credentials.json` и `token.json` с правами `600`.
- Бот работает от имени конкретного Google-аккаунта; доступ отзывается в настройках аккаунта.
- В CRM выполняется только чтение — карточки бот не изменяет.
- Письмо уходит после подтверждения в интерфейсе, автоматических рассылок нет.
- `CERT_ADMINS` ограничивает круг тех, кто может выдавать документы.

## Публикация репозитория

Репозиторий должен быть **приватным**: в `templates/` лежат оригиналы бланков с подписью
директора и печатью, а бот управляет базой действующих сертификатов.

Перед первым коммитом убедиться, что в git не попадают `.env`, `credentials.json`,
`token.json`, `issued.csv`, `emails.csv` и `out/`. В `apps_script.gs` секрет должен быть
заменён на `PASTE_SECRET_FROM_ENV` — настоящий хранится только в `.env`.

Если репозиторий всё же нужен публичный, дополнительно исключить `templates/`
и передавать бланки отдельно.
